# Changelog

## Unreleased

## v0.2.2 — 2026-10-20

- Group help by command family with aligned descriptions, focused subcommand
  listings and wrapping for narrow terminals, without emojis or protocol noise.
- Return usage errors for invalid config values and stop advertising unsupported
  standalone secret authentication. Clarify that raw output omits `END`.

## v0.2.1 — 2026-10-20

- Store preferences and credentials in one protected `config.yaml`, selected by
  `BIBLEIT_CONFIG`, without importing or merging separate legacy files. Existing
  SSH defaults continue to work; HTTP users must sign in again to save a token
  in YAML. Separate `config.json` files are ignored.
- Simplify command help to syntax and descriptions. Show the configuration file
  location in `config show` and remove `config path`.
- Require the canonical SSH `organization` capability and remove the obsolete
  `organization_status` name.

## v0.2.0

- Read HTTP books through bounded cursor pages without changing complete-book
  CLI output. Add HTTP whole-book `--limit` and `--cursor` for explicit pages,
  descriptive cursor errors and cancellation without partial successful output.

- Unify command validation, offline help, completion and descriptive errors.
- Accept translated numeric stack references with compact chapter:verse syntax
  consistently across HTTP and SSH.
- Add shared YAML preferences for transport, identity and output format.
- Standardize Scripture tables and receipts; remove stack-pop confirmation and
  routine endpoint noise. Add protected one-time secret file delivery.
- Bind the expanded REST resource surface, including stack/settings/secrets,
  quotas, personal libraries and long-poll subscriptions.
- Pin published bibleit-go v0.2.0, generated by pinned `oapi-codegen` after
  removing the Python REST generator.

## v0.1.0 — 2026-10-19

- Migrate supported HTTP commands to pinned REST v1 with workspace discovery,
  pagination, structured scripture and conditional Live writes.
- Remove command HTTP fallback and command-to-REST adapters. HTTP commands use
  REST resources directly; commands without REST equivalents are SSH-only.
- Return native REST data in raw output and schema-version-2 HTTP JSON; keep
  SSH output unchanged.
- Pin bibleit-go v0.1.0 for the versioned REST and explicit SSH clients.

## v0.0.7 — 2026-10-14

- Buffer multiline Live presentation fields during SSH subscriptions instead of
  failing with an unterminated protocol term.
- Keep large slide payloads out of human-readable Live tables and show concise
  deck/slide summaries. Render subscription verse events as readable passages;
  raw and JSON output retain the complete protocol data.
- Pin bibleit-go v0.0.4, which exposes the incomplete-term parse result to
  streaming clients. No Browsh runtime or terminal-browser prototype is shipped.

## v0.0.6 — 2026-10-13

- Update the pinned Go SDK to v0.0.3 and refresh its redistribution notice.
- Retain the v0.0.5 command surface, output schema and runtime behavior.

## v0.0.5 — 2026-10-13

## v0.0.1 — 2026-10-11

Initial Bibleit CLI release, using bibleit-go v0.0.1 and Go 1.27.1.

- Fixed production endpoints: HTTPS `https://bibleit.app` and SSH `bibleit.app:22`.
- API-token authentication, browser login/revocation and local credential storage;
  no endpoint overrides or profiles. Existing configurations tied to earlier
  endpoints require fresh authentication; see docs/releases.md for migration.
- Translation metadata/catalogues, identity, reading/search, Live management and
  SSH subscriptions, with stable text/JSON output.
- Bash, Zsh and Fish completion and destructive-command confirmation.
- Six binary archives: macOS, Linux and Windows, each amd64/arm64; Bash and
  PowerShell installers, checksums, provenance, Homebrew formula and Scoop manifest.

SSH commands require an installed OpenSSH client and verified host trust. Never
disable host-key checks to migrate an older configuration. HTTP subscriptions
require SSH. Requests reject embedded double quotes/control characters and
custom Live SECRET SET is unsupported. Catalogue numbering preserves verse gaps.

The release workflow validates native tests and the exact archives on Linux,
macOS and Windows, including PowerShell 7/5.1, Homebrew and Scoop installation.
Binaries have SHA-256 integrity checks but are not platform-signed or notarized.
Keep normal operating-system protections enabled.

Initial preparation was private. The notice-deficient v0.0.1 downloads were
withdrawn after owner approval; its source/tag remain. Public installation uses
the corrected release recorded in [launch evidence](docs/public-launch.md).

Historical service deployment evidence is maintained privately. Public client
compatibility fixtures remain in contract/.
